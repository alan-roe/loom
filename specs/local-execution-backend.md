# Local Execution Backend Specification

**Status:** Active
**Domain:** Weaver Execution
**Last Updated:** 2026-01-20

---

## 1. Overview

### Architecture Context

Weavers are isolated execution environments that run the `loom` CLI. The loom CLI inside a weaver connects BACK to loom-server's LLM proxy for Anthropic API calls. We are only replacing the execution backend, not the LLM layer.

```
┌─────────────────────────────────────────────────────────────────┐
│                        loom-server                              │
│  ┌─────────────────┐    ┌─────────────────────────────────┐    │
│  │  Provisioner    │    │  LLM Proxy (Anthropic API)      │    │
│  │  uses K8sClient │    │  ← unchanged, calls anthropic   │    │
│  │  trait ←────────┼────┼── weaver connects back here     │    │
│  └────────┬────────┘    └─────────────────────────────────┘    │
└───────────┼─────────────────────────────────────────────────────┘
            │ K8sClient trait
            ▼
    ┌───────────────────────────────────────┐
    │ KubeClient (K8s)  OR  LocalClient     │  ← WE REPLACE THIS
    └───────────────────────────────────────┘
            │
            ▼
    ┌───────────────┐
    │ Weaver        │
    │ runs: loom    │ ──→ connects to loom-server for LLM proxy
    └───────────────┘
```

### Purpose

The Local Execution Backend (`loom-server-local`) provides a `K8sClient` trait implementation that spawns weaver processes directly on the host machine instead of Kubernetes pods. It enables Loom development and usage on macOS/Linux without container orchestration.

### Goals
- Enable full Loom functionality on localhost without Kubernetes
- Maintain API compatibility with existing `Provisioner` code (zero changes needed to Provisioner)
- Support macOS as the primary target platform
- Run the same `loom` CLI that K8s weavers run

### Non-Goals
- Container isolation (processes run as current user)
- Network isolation (localhost networking)
- eBPF audit (deferred - `audit_enabled: false`)
- Multi-tenant security (single-user development use case)
- Replacing the LLM proxy layer (unchanged)

## 2. Domain Model

```rust
use std::collections::BTreeMap;
use std::path::PathBuf;
use std::sync::Arc;

use async_trait::async_trait;
use chrono::{DateTime, Utc};
use serde::{Deserialize, Serialize};
use tokio::sync::Mutex;

// Import types via re-exports from loom-server-k8s (NOT directly from k8s-openapi)
use loom_server_k8s::{
    K8sClient, K8sError, LogOptions, LogStream, AttachedProcess, TokenReviewResult,
    Pod, Namespace,
};
// These must come from k8s-openapi directly (not re-exported)
use k8s_openapi::apimachinery::pkg::apis::meta::v1::ObjectMeta;

/// K8s Pod → Local Process (internal implementation detail)
/// Simpler than spec originally proposed - tmux session name derived from metadata.id
pub struct LocalWeaver {
    pub metadata: WeaverMetadata,
    pub status: WeaverStatus,
    pub dir: PathBuf,  // Effective working directory (resolved from metadata.working_dir)
}

impl LocalWeaver {
    /// Derive tmux session name from metadata
    pub fn session_name(&self) -> String {
        format!("weaver-{}", self.metadata.id)
    }
}

/// Weaver status (local implementation, not imported from loom-server-weaver)
#[derive(Debug, Clone, Copy, PartialEq, Eq)]
pub enum WeaverStatus {
    Running,
    Succeeded,
    Failed,
    Unknown,
}

/// K8s Labels/Annotations → Metadata file (persisted to .loom/metadata.json)
/// Note: Labels flow FROM Pod spec INTO metadata (not generated by metadata)
#[derive(Debug, Clone, Serialize, Deserialize)]
pub struct WeaverMetadata {
    pub id: String,                           // Plain String, not WeaverId type
    pub name: String,                         // Derived: "weaver-{id}"
    pub image: String,
    pub labels: BTreeMap<String, String>,     // Extracted from Pod spec labels
    pub env_vars: Vec<(String, String)>,      // Extracted from Pod container spec
    pub created_at: DateTime<Utc>,
    #[serde(default)]
    pub ttl_hours: Option<u32>,               // Optional TTL for cleanup
    #[serde(default)]
    pub working_dir: PathBuf,                 // User's project directory (empty = use fallback)
}

impl WeaverMetadata {
    pub fn new(id: String, image: String, labels: BTreeMap<String, String>, working_dir: PathBuf) -> Self {
        let name = format!("weaver-{id}");
        Self {
            id, name, image, labels, working_dir,
            env_vars: Vec::new(),
            created_at: Utc::now(),
            ttl_hours: None,
        }
    }

    pub fn with_env_vars(mut self, env_vars: Vec<(String, String)>) -> Self {
        self.env_vars = env_vars;
        self
    }

    pub fn with_ttl(mut self, ttl_hours: u32) -> Self {
        self.ttl_hours = Some(ttl_hours);
        self
    }

    pub fn is_expired(&self) -> bool {
        if let Some(ttl) = self.ttl_hours {
            let expires_at = self.created_at + chrono::Duration::hours(ttl as i64);
            Utc::now() > expires_at
        } else {
            false
        }
    }

    /// Returns the effective working directory, handling backward compatibility
    /// for legacy metadata files that lack a working_dir field.
    pub fn effective_working_dir(&self, config: &LocalConfig) -> PathBuf {
        if self.working_dir.as_os_str().is_empty() {
            config.weaver_dir(&self.id)  // Legacy fallback
        } else {
            self.working_dir.clone()
        }
    }
}

/// Our implementation - parallel to KubeClient in loom-server-k8s
pub struct LocalClient {
    config: LocalConfig,
    weavers: Arc<Mutex<BTreeMap<String, LocalWeaver>>>,  // BTreeMap by String id
}

#[derive(Debug, Clone)]
pub struct LocalConfig {
    pub base_dir: PathBuf,      // ~/loom-weavers
    pub default_image: String,  // loom:latest
    pub server_url: String,     // For LOOM_SERVER_URL env var
}
```

## 3. Aggregate Invariants

- Only one process per WeaverId (enforced by PID file locking)
- Metadata directory (`~/loom-weavers/weaver-{id}/.loom/`) exists before process spawn
- Working directory (`metadata.working_dir`) exists before tmux session creation
- **Atomic metadata persistence**: Metadata file is written atomically via write-to-temp-then-rename pattern. This prevents corruption if the server crashes mid-write.
- Process cleanup removes tmux session and metadata directory
- **Working directory preservation**: User-specified working directories are never deleted on weaver cleanup
- Each weaver runs inside a tmux session (matches K8s behavior, survives server restart)
- **Startup reconciliation**: On LocalClient init, scan existing weaver directories, verify tmux sessions exist and processes are alive, reconcile in-memory state with filesystem
- **TTL expiration data**: Each weaver stores `created_at` and `ttl_hours` in metadata. The Provisioner-level cleanup task (in `loom-server-weaver`) calculates expiration and deletes expired weavers. LocalClient does not run its own cleanup task.

## 4. Behaviors

### Create Weaver (implements `create_pod`)
**Given** a Pod spec with labels, annotations, and container config
**When** `create_pod` is called
**Then**
  - Extract weaver ID from `metadata.name` (format: `weaver-{id}`)
  - Extract labels from Pod spec's `metadata.labels` into WeaverMetadata
  - Extract image from Pod spec's `spec.containers[0].image`
  - Extract env vars from Pod spec's `spec.containers[0].env`
  - **Resolve working directory:**
    1. Check `LOOM_WORKING_DIR` env var → use as `working_dir` if present and directory exists
    2. Check `loom.dev/working-dir` annotation → use if present and directory exists
    3. Fallback to `~/loom-weavers/weaver-{id}/` (creates if not exists)
  - Create metadata directory `~/loom-weavers/weaver-{id}/.loom/`
  - Write metadata atomically: serialize to JSON, write to `.loom/metadata.json.tmp`, call `fsync`, rename to `.loom/metadata.json`
  - Create empty `.loom/output.log` file
  - **Git clone (only when using fallback working_dir):**
    - If `LOOM_REPO` env var in pod spec AND working_dir is the fallback location → `git clone` into `working_dir`
    - If `LOOM_REPO` specified but working_dir is user-specified → skip clone (existing project)
  - Create tmux session with working_dir as cwd: `tmux new-session -d -s weaver-{id} -c {working_dir}`
  - Configure tmux logging: `tmux pipe-pane -t weaver-{id} -o 'cat >> ~/loom-weavers/weaver-{id}/.loom/output.log'`
  - Build env string from metadata.env_vars
  - Run loom CLI with exec: `tmux send-keys -t weaver-{id} "exec env {env_vars} LOOM_SERVER_URL={url} loom" Enter`
  - Get pane PID: `tmux display-message -t weaver-{id} -p '#{pane_pid}'`
  - Write pane PID to `.loom/pid`
  - Return Pod with status.phase = "Running"
  - Tmux session name is derived from id via `session_name()` method
  - Using `exec` means the pane dies when loom exits (detectable via `#{pane_dead}`)
  - Provisioner ignores the return value and polls via `get_pod` separately

### Get Weaver Status (implements `get_pod`)
**Given** a pod name (format: `weaver-{uuid}`)
**When** `get_pod` is called
**Then**
  - Parse WeaverId from pod name
  - Check tmux session exists: `tmux has-session -t weaver-{id}` (exit code 0 = exists)
  - If session exists, check pane status: `tmux display-message -t weaver-{id} -p '#{pane_dead}'`
  - Map to phase:
    - Session exists AND pane alive → "Running"
    - Session exists AND pane dead → "Succeeded" (loom exited cleanly via exec)
    - Session missing → "Failed" (unexpected termination)
  - Return Pod with all required fields populated (see Minimum Pod Fields)

### List Weavers (implements `list_pods`)
**Given** a label selector (e.g., `loom.dev/managed=true`)
**When** `list_pods` is called
**Then**
  - Scan `~/loom-weavers/weaver-*/` directories
  - Filter by metadata fields matching selector (simple `key=value` parsing)
  - Return list of Pod objects

### Delete Weaver (implements `delete_pod`)
**Given** a pod name and grace period
**When** `delete_pod` is called
**Then**
  - Parse weaver ID from pod name (strip `weaver-` prefix)
  - Kill tmux session: `tmux kill-session -t weaver-{id}` (sends SIGHUP to all processes)
  - Wait `grace_period_seconds` for clean shutdown (allows loom to save state)
  - Remove `~/loom-weavers/weaver-{id}/.loom/` metadata directory
  - **Do NOT remove working_dir** if it was user-specified (only remove metadata)
  - Remove fallback working_dir only if it equals `~/loom-weavers/weaver-{id}/`
  - Remove from in-memory `weavers` map
  - Log deletion with tracing

### Stream Logs (implements `stream_logs`)
**Given** a pod name and LogOptions
**When** `stream_logs` is called
**Then**
  - Parse weaver ID from pod name
  - Open `.loom/output.log` (fed by tmux pipe-pane, container param is ignored)
  - If `opts.tail > 0`, seek to file end, read backward to find last N lines, stream from there
  - **Follow mode**: The stream continues indefinitely, yielding new bytes as they are appended to the log file. This matches K8s behavior where `follow: true` keeps the connection open. Implementation uses periodic file polling (100-500ms interval) or platform-specific file watching (e.g., `kqueue` on macOS, `inotify` on Linux via `notify` crate).
  - Stream chunks as `Bytes` (not necessarily line-delimited - matches K8s raw byte streaming)
  - Return `Pin<Box<dyn Stream<Item = Result<Bytes, std::io::Error>> + Send>>`
  - Stream terminates when: (a) the weaver process exits and all buffered output is read, or (b) the client disconnects

### Attach Terminal (implements `exec_attach`)
**Given** a pod name
**When** `exec_attach` is called
**Then**
  - Parse WeaverId from pod name
  - Spawn `tmux attach-session -t weaver-{id}` with PTY via `portable-pty`
  - Return `AttachedProcess { stdin, stdout }` connected to PTY
  - **Note**: tmux session survives server restart; attach always works for live weavers

### Validate Token (implements `validate_token`)
**Given** any token and audiences slice
**When** `validate_token(token: &str, audiences: &[&str])` is called
**Then**
  - Ignore `token` parameter (local dev has no auth)
  - Pass through `audiences` parameter to response
  - Return `TokenReviewResult::authenticated(
        "local-dev-user".to_string(),
        vec!["system:authenticated".to_string()],  // Groups
        HashMap::new(),                             // Extra info
        audiences.iter().map(|s| s.to_string()).collect(),  // Audiences
    )`

### Get Namespace (implements `get_namespace`)
**Given** namespace name (ignored)
**When** `get_namespace` is called
**Then**
  - Ensure `~/loom-weavers/` exists (create if not)
  - Return `Namespace::default()`

## 6. Success Criteria

All criteria are requirements. The system satisfies these properties:

- All 8 K8sClient trait methods are implemented with identical semantics to KubeClient
- Existing Provisioner works without modification (LocalClient is a drop-in replacement)
- Weaver lifecycle works: create → get → attach → delete
- Loom CLI in weaver reaches loom-server LLM proxy via LOOM_SERVER_URL
- Log streaming returns valid `LogStream` with continuous follow support
- TTL cleanup works: Provisioner's `cleanup_expired_weavers()` correctly identifies and deletes expired local weavers based on `created_at` and `ttl_hours` metadata
- Process isolation: each weaver runs in separate tmux session with dedicated directory
- Graceful shutdown: tmux kill-session → wait grace period → cleanup metadata
- Startup reconciliation recovers existing weavers (tmux sessions survive server restart)
- Attach works after server restart (tmux session persistence)
- Existing directories: Weaver creates in user-specified `LOOM_WORKING_DIR`
- Directory preservation: User's working_dir preserved on weaver deletion
- Metadata isolation: `.loom/` metadata is always under `base_dir`, separate from working directory
- Crash recovery: Atomic metadata writes prevent corruption on unexpected termination

## 9. Implementation Notes

### Directory Structure

Local weavers work on **existing directories** (user's actual projects), not isolated sandboxes.
The metadata directory and working directory are separate concepts:

```
Metadata directory (always created):
~/loom-weavers/weaver-{id}/.loom/
├── metadata.json    # Weaver metadata (id, name, image, labels, env_vars, working_dir, created_at, ttl_hours)
├── pid              # tmux pane PID (loom process PID due to exec)
└── output.log       # Captured output (via tmux pipe-pane)

Working directory (tmux session cwd):
{working_dir}/                    # User-specified project directory
├── src/                          # Existing project files
├── Cargo.toml                    # User's actual project
└── ...
```

**Working directory resolution:**
1. If `LOOM_WORKING_DIR` env var specified in Pod spec → use that path
2. If `loom.dev/working-dir` annotation specified → use that path
3. Otherwise → fallback to `~/loom-weavers/weaver-{id}/`

**Git clone behavior:**
- If `LOOM_REPO` env var specified AND working_dir is the fallback location → clone into fallback dir
- If `LOOM_REPO` specified but working_dir points elsewhere → ignore (user's existing project takes precedence)

### What Runs in a Weaver

Both K8s and local weavers use tmux for session persistence:

**K8s**: `tmux new-session -A -s loom "loom"`
**Local**: Same pattern, managed via `std::process::Command`

```rust
use std::process::Command;

// Create detached tmux session
Command::new("tmux")
    .args(["new-session", "-d", "-s", &session_name, "-c", &workspace_dir])
    .status()?;

// Enable logging via pipe-pane
Command::new("tmux")
    .args(["pipe-pane", "-t", &session_name, &format!("cat >> '{}'", log_path)])
    .status()?;

// Start loom CLI with exec (replaces shell, pane dies when loom exits)
Command::new("tmux")
    .args(["send-keys", "-t", &session_name,
           &format!("exec env LOOM_SERVER_URL='{}' loom", server_url), "Enter"])
    .status()?;

// Get pane PID for status tracking
let output = Command::new("tmux")
    .args(["display-message", "-t", &session_name, "-p", "#{pane_pid}"])
    .output()?;
let pane_pid = String::from_utf8_lossy(&output.stdout).trim().to_string();

// For exec_attach: spawn `tmux attach-session -t {session}` with PTY
let pair = pty_system.openpty(PtySize::default())?;
let cmd = CommandBuilder::new("tmux");
cmd.args(["attach-session", "-t", &session_name]);
let child = pair.slave.spawn_command(cmd)?;
// pair.master needs sync→async wrapper (see below)
```

### PTY Async Bridge

portable-pty provides synchronous I/O, but `AttachedProcess` requires `AsyncRead`/`AsyncWrite`. Use `tokio::task::spawn_blocking` with channels:

```rust
use bytes::Bytes;
use pin_project_lite::pin_project;
use tokio::sync::mpsc;

const CHANNEL_BUFFER_SIZE: usize = 32;
const READ_BUFFER_SIZE: usize = 4096;

pin_project! {
    pub struct PtyAsyncReader {
        rx: mpsc::Receiver<io::Result<Bytes>>,
        buffer: Bytes,  // Leftover bytes from partial reads
    }
}

impl PtyAsyncReader {
    pub fn new(mut reader: Box<dyn Read + Send>) -> Self {
        let (tx, rx) = mpsc::channel(CHANNEL_BUFFER_SIZE);
        tokio::task::spawn_blocking(move || {
            let mut buf = vec![0u8; READ_BUFFER_SIZE];
            loop {
                match reader.read(&mut buf) {
                    Ok(0) => { let _ = tx.blocking_send(Ok(Bytes::new())); break; }
                    Ok(n) => {
                        let bytes = Bytes::copy_from_slice(&buf[..n]);
                        if tx.blocking_send(Ok(bytes)).is_err() { break; }
                    }
                    Err(e) => { let _ = tx.blocking_send(Err(e)); break; }
                }
            }
        });
        Self { rx, buffer: Bytes::new() }
    }
}

// PtyAsyncWriter uses poll_reserve to properly integrate with async waker
impl AsyncWrite for PtyAsyncWriter {
    fn poll_write(self: Pin<&mut Self>, cx: &mut Context<'_>, buf: &[u8]) -> Poll<io::Result<usize>> {
        let this = self.project();

        // poll_reserve registers the waker if channel is full - CRITICAL for correctness
        // Using try_send + Poll::Pending without waker registration causes hangs
        match this.tx.poll_reserve(cx) {
            Poll::Ready(Ok(permit)) => {
                let bytes = Bytes::copy_from_slice(buf);
                let len = bytes.len();
                permit.send(bytes);
                Poll::Ready(Ok(len))
            }
            Poll::Ready(Err(_)) => Poll::Ready(Err(BrokenPipe)),
            Poll::Pending => Poll::Pending,  // Waker properly registered by poll_reserve
        }
    }
}
```

### Atomic Metadata Write

To prevent corruption on crash, metadata is written atomically:

```rust
use std::io::Write;

fn write_metadata_atomic(metadata_path: &Path, metadata: &WeaverMetadata) -> io::Result<()> {
    let json = serde_json::to_string_pretty(metadata)?;
    let temp_path = metadata_path.with_extension("json.tmp");

    // Write to temp file
    let mut file = fs::File::create(&temp_path)?;
    file.write_all(json.as_bytes())?;
    file.sync_all()?;  // Ensure data reaches disk

    // Atomic rename (POSIX guarantees atomicity)
    fs::rename(&temp_path, metadata_path)?;
    Ok(())
}
```

### Log Follow with File Watching

Log streaming with follow mode uses the `notify` crate for efficient file watching:

```rust
use notify::{Watcher, RecursiveMode, recommended_watcher};
use tokio::sync::mpsc;

pub struct LogFollower {
    file: tokio::fs::File,
    watcher: RecommendedWatcher,
    notify_rx: mpsc::Receiver<()>,
    position: u64,
}

impl LogFollower {
    pub async fn new(log_path: &Path) -> io::Result<Self> {
        let file = tokio::fs::File::open(log_path).await?;
        let position = file.metadata().await?.len();

        // Set up file watcher
        let (notify_tx, notify_rx) = mpsc::channel(16);
        let mut watcher = recommended_watcher(move |_| {
            let _ = notify_tx.blocking_send(());
        })?;
        watcher.watch(log_path, RecursiveMode::NonRecursive)?;

        Ok(Self { file, watcher, notify_rx, position })
    }

    // Returns next chunk of bytes, waiting for writes if needed
    pub async fn next_chunk(&mut self) -> io::Result<Option<Bytes>> {
        loop {
            // Try to read any new data
            let current_len = self.file.metadata().await?.len();
            if current_len > self.position {
                let mut buf = vec![0u8; (current_len - self.position) as usize];
                self.file.seek(SeekFrom::Start(self.position)).await?;
                let n = self.file.read(&mut buf).await?;
                self.position += n as u64;
                return Ok(Some(Bytes::from(buf[..n].to_vec())));
            }

            // Wait for file change notification
            if self.notify_rx.recv().await.is_none() {
                return Ok(None);  // Watcher closed, stream ends
            }
        }
    }
}
```

The stream yields `Bytes` chunks as the log file grows, matching K8s behavior.

### Tmux Error Message Variations

Tmux error messages vary by version and state. Handle these variations:

| Condition | Possible Messages |
|-----------|-------------------|
| Session missing | `"session not found"` OR `"can't find session"` |
| No tmux server | `"no server running"` OR `"no sessions"` |

When checking for "not found" conditions, check for both message variants.

### Label Selector Parsing

Support simple `key=value` selectors (what Provisioner uses):

```rust
pub fn matches_selector(labels: &BTreeMap<String, String>, selector: &str) -> bool {
    if selector.is_empty() {
        return true;
    }
    for part in selector.split(',') {
        let part = part.trim();
        if part.is_empty() { continue; }
        if let Some((key, value)) = part.split_once('=') {
            let key = key.trim();
            let value = value.trim();
            match labels.get(key) {
                Some(label_value) if label_value == value => continue,
                _ => return false,
            }
        } else if !labels.contains_key(part) {
            return false;
        }
    }
    true
}
```
